# Stripchat India Agency — Website

Simple, mobile-first 3-page website for a verified Stripchat creator agency in India.

## Pages

- `/` — Home: what the work is, requirements, earnings, privacy, videos, FAQ, WhatsApp CTA
- `/apply` — 2-field application form (name, city, 18+ confirm) that opens WhatsApp with a pre-filled message
- `/help` — Help / safety / agency switch / FAQ

Old routes (`/about`, `/services`, `/why-join`, `/requirements`, `/faq`, `/contact`, `/privacy`, `/terms`) redirect to the relevant new pages via `next.config.mjs`.

## Stack

- Next.js 14 (App Router)
- Tailwind CSS v4
- TypeScript
- Lucide icons

## Run locally

```bash
npm install
npm run dev
```

Open http://localhost:3000

## Build

```bash
npm run build
npm start
```

## Search and link previews

- Each page has a canonical URL, page-specific title and description, Open Graph tags, and a large-image X/Twitter card.
- Set `SITE_URL` to the production HTTPS origin in `.env.local` and in the deployment environment. Use a domain your organization controls; production builds fail when this is missing, to avoid publishing canonical URLs for somebody else's domain. Canonicals, structured data, the share-card domain, `robots.txt`, and `sitemap.xml` all use this origin. This setting must be present in the production build environment because these routes are statically generated.
- `NEXT_PUBLIC_CONTACT_EMAIL` is optional. Leave it blank to hide the email contact option; WhatsApp and phone remain available. If set, use a working mailbox your organization controls.
- `/opengraph-image` is generated at build time for share previews. `/robots.txt` and `/sitemap.xml` are also generated by the app.
- `public/llms.txt` is a short, domain-independent site guide. It is not a Google ranking factor or a guarantee of inclusion in AI search.
- Public crawling, including AI crawlers that honor robots.txt, remains allowed by the general rule, as selected by the site owner. No bot-specific overrides are needed while this allow-all policy is in effect.
- To verify the site in Google Search Console, set `GOOGLE_SITE_VERIFICATION` to the verification code from Search Console in the deployment environment, then redeploy. Add `https://<your-domain>/sitemap.xml` in Search Console after deployment.
- Keyword meta tags and keyword stuffing are intentionally avoided: search rankings depend on useful, accurate page content, and Google does not use the keywords meta tag for ranking.
- Social networks may cache previews; use their link-preview inspectors after deployment if a shared image or description looks stale.
